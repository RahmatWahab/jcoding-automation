## Runtime and build

- Java 21 application plugin and `com.jcoding.workflow.Main` entry point: `build.gradle:1-18`. Gradle wrapper 8.14.4: `gradle/wrapper/gradle-wrapper.properties:3`.
- Runtime dependencies are Jackson databind 2.17.3, SQLite JDBC 3.46.1.0, SLF4J 2.0.16, and Logback 1.5.15; tests use JUnit Jupiter 5.11.4 and AssertJ 3.26.3: `build.gradle:20-29`. There is no direct model SDK dependency; the program launches the Codex CLI.
- Gradle `check` runs JUnit and `checkstyleMain`; `checkstyleTest` is disabled (`build.gradle:31-45`). Main Checkstyle currently checks only method length and cyclomatic complexity (`config/checkstyle/checkstyle.xml:12-25`); 24 named legacy methods are exempt (`config/checkstyle/legacy-methods.xml:4-29`). This is a narrow static analysis gate, not general lint/security analysis.
- `autonomyReleaseGate` depends on `check` and a shell fixture test, then requires a JUnit XML report with nonzero tests and at least eight `AutonomyBusinessValueMockTest` cases (`build.gradle:47-83`). It counts all XML suites but does not prove any live GitHub/model integration. CI invokes this task with GitHub and model credential variables empty (`.github/workflows/autonomy-gate.yml:13-36`).
- `scripts/run_once.sh:14-18` bypasses runtime build if `job_start` is not true; enabled runs build a content-hashed immutable distribution, serialize publication with `flock`, reject changed inputs, and run in `setsid` (`scripts/run_once.sh:42-115`). Fixture tests cover this launcher (`scripts/tests/run_once_test.sh:45-147`).
- `scripts/cron-launcher.sh:12-23` sources a mode-600 env file. Its fallback scans `.bashrc` and `eval`s the first line beginning `export GH_TOKEN=` (`scripts/cron-launcher.sh:25-36`), so that line is executable shell, not parsed data. The risk is local arbitrary command execution if this file is attacker-modifiable; no exploit was run.
- Example config defaults to dry-run and disallows push/PR/comments/merge (`config/config.json.example:16-18,129-147`), requires explicit verification checks but supplies none (`config/config.json.example:149-165`), and configures a bubblewrap isolated worker with gateway limits (`config/config.json.example:44-119`). Therefore the example is not ready for autonomous delivery without repository-specific checks and required CI names.

## Verification limitations and recommended tests

The offline suite cannot prove model output quality, real provider gateway compatibility, real GitHub permissions/branch protection, remote effect idempotency, or completion of a representative software task. Add an isolated disposable repository task with a real worker under strict local permissions, then validate a criterion-linked code change, failing-test repair, final diff, and durable resume. Keep live PR/merge validation behind explicit authorization and separate canary evidence. Do not equate the passing count of mock tests with end-to-end autonomy.
