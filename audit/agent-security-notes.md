# Security and reliability audit notes (delegated scope)

> Historical draft, 2026-10-17. Several findings below were addressed in the current working tree (notably Git process isolation/hook restrictions, explicit staging, bounded GitHub output and lock-token ownership). Use `02-gap-analysis.md` for current findings.

Scope: `Config`, `CodexRunner`, `BoundedProcess`, `WorkerIsolation`, `ActionPolicy`, `DeploymentPolicy`, `GitOperations`, `GitHub`, `WorkflowLock`, `RuntimeIdentity`, `HostReadiness`, `ProviderCanary`, shell scripts, and Python isolation resources. Source inspection only; no live provider, GitHub, reset, cron, or worker invocation. Existing uncommitted files were preserved. Applied the `cybersecurity` skill and its `06_ai_security.md` playbook for trust, tool, and credential boundaries.

## Positive implemented controls

- `CodexRunner.java:115-154` fixes the CLI sandbox to workspace write or read only, forbids sandbox bypass, disables tool network access, and binds model requests to a scoped gateway in bubblewrap mode. `Config.java:180-182` validates key settings.
- `WorkerIsolation.java:24-32,35-79,119-158` restricts child environment, unshares namespaces, mounts the repository, applies `prlimit`, and runs a short lived, token guarded model gateway. `model_gateway.py:26-43,46-69,104-152` requires HTTPS, checks public DNS addresses, limits model and hosted tools, rejects remote media, caps requests/output, and avoids provider redirects. This is code evidence; host support remains unverified.
- `CodexRunner.java:336-465` bounds event line and final output size and reports completed agent messages separately from command failures. `BoundedProcess.java:15-63` bounds output and deadline and tries to terminate descendants. `ActionPolicy.java:16-48` enforces cancellation, dry run and external mutation flags when wired. `GitOperations.java:280-295,344-372` and `GitHub.java:90-96,334-387` add journal observation for important remote effects. `DeploymentPolicy.java:70-153` gates unattended modes on configuration and canary evidence.

## Findings

### SEC-01 — Git controller process inherits broad host authority (high, verified by code)

`GitOperations.java:582-589` executes Git through `BoundedProcess.run(..., null, ...)`; `BoundedProcess.java:23-26` only replaces the environment when a non-null map is supplied. Git therefore inherits all controller environment variables and executes outside bubblewrap. Git commands including fetch, merge, add, commit, and push run against repository controlled `.git` config and hooks (`GitOperations.java:354-371,436-441,494-518`). A malicious or compromised target repo can set a `pre-commit` hook or Git transport/helper to run code with provider and GitHub credentials during controller commit/fetch/push. The worker's clean environment does not protect this path. Reproduce safely using a temporary repository and a benign hook that writes a sentinel; invoke `commitAndPush` with a fake local remote and verify the hook receives a canary environment variable. Recommended: isolate Git operations, use a narrow environment and trusted CLI, disable hooks (`core.hooksPath` to an empty trusted directory), constrain transport/protocol and remote URL, and pass only action scoped credentials. Run a local mock test before enabling external mutation.

### SEC-02 — Secret path filter can miss staged secrets and copies (high, verified by code)

`GitOperations.java:184-193` parses human `git status --porcelain` line by line with `substring(3)`; `GitOperations.java:380-406` strips only first/last quotes and matches path names; `GitOperations.java:354` then runs blanket `git add -A`. Git porcelain escapes special characters and rename records can contain `old -> new` path syntax, so the validation may inspect a different string than the path Git stages. It also only recognizes selected name patterns; a secret in `config/prod.json` or `.npmrc` can be staged. Concrete scenario: model creates an untracked file containing a credential under a benign filename; it is not on the denylist and `git add -A` stages it. Recommend `git status --porcelain=v1 -z` or libgit2 path parsing, stage explicit validated paths, validate the actual staged index and file contents before commit, and use an allowlist of paths plus a secret scanner. Test filenames with spaces, quotes, renames, symlinks, and benign named files containing canary credentials. The code based issue is confirmed; actual exfiltration was not run.

### SEC-03 — Local development worker lacks outer isolation (high in development, verified by code)

`Config.java:180-182,211-213` permits `codex.isolation=native` except when auto merge is enabled. `CodexRunner.java:217-234` only creates `WorkerIsolation` for bubblewrap; native mode runs Codex with the operator's real home and optional `CODEX_HOME`. The CLI sandbox remains active (`CodexRunner.java:131-140`), but the controller cannot enforce that it stays secure if the external Codex tool fails or user settings conflict; repository content can prompt tool use, and the worker can see the operator's Codex profile. `DeploymentPolicy.java:76-78` correctly requires bubblewrap for unattended rollout. Keep development mode explicitly local and do not treat it as a production trust boundary. Verify in a controlled temp repo that native Codex cannot read files outside the workspace and cannot use network tools; keep the deployment gate.

### SEC-04 — Worker can read broad host runtime mounts (medium, verified by code)

`WorkerIsolation.java:44-47,81-90` accepts arbitrary configured `runtime_read_paths` after canonicalizing, except ancestors of controller home and paths matching `.codex/.ssh/.aws`; a path such as `/etc`, `/var`, or another user's home could expose unrelated host data inside the model worker. The base mounts already expose selected `/etc` files (`WorkerIsolation.java:40-43`). Configuration is operator controlled, so this is a misconfiguration risk rather than a repository prompt injection bypass. Restrict runtime mounts to explicit package/tool directories; reject user homes, `/etc` roots, credentials, device and sensitive service paths. Add validation tests for parent directories and symlink aliases.

### SEC-05 — GitHub CLI result and log handling is unbounded and not uniformly redacted (medium, verified by code)

`GitHub.java:495-552` captures stdout and stderr in unrestricted `ByteArrayOutputStream`s and waits before joining readers. A large or endless response consumes memory until the timeout. `GitHub.java:173-176` throws raw stderr/stdout as an exception; unlike `CodexRunner.java:101-113`, it has no credential redaction, and upstream callers may log that exception. `GitHub.java:149-152` executes a configurable `cli` in the full host environment. Bound each stream, terminate on size, redact configured credential values before logging or persisting diagnostics, validate the executable path, and use a minimal environment. Test a fake CLI emitting >8 MiB and a canary token in stderr.

### SEC-06 — Shell launchers trust mutable local code and shell content (medium, verified by code)

`cron-launcher.sh:13-22` sources an operator selected file after checking mode `600` but not owner, path type, or symlink target. `cron-launcher.sh:27-35` uses `eval` on a line read from `.bashrc`. Both run with launcher privileges. `run_once.sh:49-60,76-83` hashes source then runs Gradle against the checkout; a malicious build script runs before the second hash comparison, and Gradle inherits controller environment. The assumption is that the controller repository and secret file are trusted. Enforce owner and regular file checks, parse the token assignment without `eval`, pin a reviewed release/build artifact for unattended launch, and avoid exposing provider credentials to Gradle. A local test can use inert assignments and a fake Gradle executable; do not run production jobs.

### SEC-07 — Lock recovery may race a live slow owner (medium, code based and unverified experimentally)

`WorkflowLock.java:107-155` declares a live owner stale solely from heartbeat age; it deletes owner file/directory and recreates them without an atomic compare and swap. `WorkflowLock.java:159-183` checks only PID and presence of a token, not a token captured at acquisition. If old and new contenders share a PID through process restart or PID reuse, a stale owner could believe it still owns the lock; `release(null)` at `WorkflowLock.java:185-205` similarly allows same PID to release a replacement lock. The common case is mitigated by heartbeat and PID checks; the race needs a concurrency test. Store the acquired token in the object, require exact token on refresh/release, and recover by atomic rename or OS file lock. Test forced stale heartbeat with two local processes and barrier synchronization.

### SEC-08 — Canary evidence does not prove real coding workflow (medium, verified by code)

`ProviderCanary.java:20-47` sends a fixed read only reply request. `DeploymentPolicy.java:113-141` admits autonomous mode based on fingerprint and fresh provider/canary receipts; `recordCanary` at `DeploymentPolicy.java:144-153` records after one delivered PR head, CI checks, and review gate. These are useful gates but do not establish prompt injection resistance, all Git paths, recovery, cost, or task quality. Treat admission as limited operational readiness, then gate wider rollout on measured task evaluations and incident thresholds.

### SEC-09 — Cancellation is cooperative at side effect boundary and polling (medium, verified by code)

`ActionPolicy.java:16-29` checks job control when called. `CodexRunner.java:245-265` checks heartbeat at start and every configured interval, and `BoundedProcess.java:40-46` polls a heartbeat if provided. Git uses `BoundedProcess.run(..., null, ...)` (`GitOperations.java:582-589`), so a running Git command only stops on its 120 second timeout, and GitHub default runner only checks its timeout (`GitHub.java:516-532`). A cancellation can arrive after a mutation guard and before a remote effect. Journal observation reduces duplication but does not make external actions transactional. Add cancellation callbacks inside Git/GitHub process supervisors and recheck authorization immediately before each external mutation; record action grants and effects durably.
