# C4 Architecture Sketch

## Context

`jcoding-automation` is a local Java replacement for the frozen Python Codex
coding automation. It is operated by a human through GitHub, local cron, Git,
GitHub CLI, and Codex CLI. It never merges PRs automatically.

## Container

```text
Human operator
  -> GitHub repository
  -> local jcoding-automation Java application
       -> Git CLI
       -> GitHub CLI / GraphQL
       -> Codex CLI
       -> SQLite state
       -> JSON configuration
       -> logs
```

## Components

```text
bootstrap
  -> dependency wiring, version command, graceful shutdown
config
  -> JSON loading and schema validation
scheduler
  -> cron invocation and job-control eligibility
execution
  -> process execution and streamed progress
locking
  -> one-active-run guarantee
workflow
  -> phases and pure decisions
story
  -> EPIC/story selection
git
  -> local branch and head operations
github
  -> issues, PRs, reviews, CI, merge state
review
  -> review threads, replies, resolution, review gates
codex
  -> prompt execution and result parsing
validation
  -> validation plans and evidence
persistence
  -> SQLite state and event journal
logging
  -> structured logs and redaction
housekeeping
  -> retention and cleanup policy
provider
  -> replaceable provider abstractions
```

## S002 Boundary

S002 creates the Gradle foundation, bootstrap command, package boundaries,
interface contracts, architecture decisions, and executable fitness checks. It
does not implement workflow behavior, GitHub mutations, Codex execution,
locking, SQLite persistence, or cron installation; those are owned by later
stories in EPIC #1.
